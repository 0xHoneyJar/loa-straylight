# Finn enforcement mapping — Straylight transitions to Finn runtime points

> Status: Phase 10. **Pre-integration handoff packet, in
> `loa-straylight` only.** This table maps each Straylight
> transition or primitive to the proposed Finn runtime enforcement
> point, the required input, the required output, the fail-closed
> condition, the audit-receipt requirement, and the related
> Hounfour schema candidate. **Filing this against `loa-finn` is
> not part of Phase 10.** Nothing here imports from `loa-finn`,
> edits any sibling repo, or changes Phase 0–9 runtime behavior.

## How to read this table

| Column | Meaning |
|---|---|
| **Straylight transition / primitive** | The transition name (per `EstateTransition.transition_type`) or runtime primitive (per the wedge's public API) the row covers. |
| **Current Straylight local source** | Where the wedge implements this primitive today. |
| **Future Finn enforcement point** | The Finn-side runtime gate that should enforce this primitive after consuming stable contracts. |
| **Required input** | The shape Finn must accept and pass into the wedge's primitive. |
| **Required output** | The shape Finn must produce (decision, receipt, audit event, pack) on success. |
| **Fail-closed condition** | What Finn must do when the gate is unavailable, the policy denies, the signer is incompetent, or storage refuses. |
| **Audit / receipt requirement** | The audit event(s) and receipt(s) that MUST be emitted on every applied or denied call. |
| **Related Hounfour schema candidate** | The schema id (or candidate-name) Finn consumes for shape. `—` if no Hounfour schema is the load-bearing input. |
| **Notes** | Constraints, architecture-spec citations, and "stays in Straylight" runtime references. |

## Promotion-chain reminder

Per [`README.md`](../../README.md#promotion-and-demotion-boundaries),
the wedge's promotion chain is:

```text
memory
  → belief
  → instruction
  → plan
  → permission
  → action
  → commitment
  → permanence
```

Each step in this chain is a transition Finn must enforce. Skipping
a step (e.g. promoting a memory directly to a permission) is a
boundary violation that the wedge tests refuse and that Finn's
runtime gate must equally refuse. The transition column above
applies recursively: every promotion is a `classify_assertion` (or
its post-extraction successor) with a *role-competent* signer for
the target class.
